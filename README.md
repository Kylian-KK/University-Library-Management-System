## University Library Management System with SQL Server

Objective

This project implements a relational database for managing a university library. It covers members, books, loans, fines and audit history through a set of SQL Server tables, stored procedures, triggers and test scenarios.

The system is designed to automate common library operations while enforcing basic business rules. These operations include registering members, cataloguing books, recording loans, processing book returns, calculating late penalties, updating member statuses and auditing changes made to key entities.

Functional Scope

The database supports the following activities:

| Function | Description |
| --- | --- |
| Member management | Store member identity, email, type, status and borrowing limit |
| Book management | Store ISBN, title, author and available quantity |
| Loan management | Record borrowings, due dates and loan statuses |
| Fine management | Register penalties generated by late returns |
| Eligibility control | Check whether a member can borrow a book |
| Automatic business rules | Update borrowing limits and loan statuses through triggers and procedures |
| Audit trail | Record insertions, updates and deletions in an audit table |
| Reporting | Display overdue loans and the associated number of late days |




Database Schema

The database is named Bibliotheque_Universitaire and contains five tables.

| Table | Purpose | Main relationships |
| --- | --- | --- |
| `Membre` | Stores library members and their borrowing status | Referenced by `Emprunt` |
| `Livre` | Stores the book catalogue and available quantities | Referenced by `Emprunt` |
| `Emprunt` | Stores borrowing transactions | References `Membre` and `Livre`; referenced by `Amende` |
| `Amende` | Stores fines associated with loans | References `Emprunt` |
| `HistoriqueModifications` | Stores audit events generated by triggers | Independent audit table |




The relationship structure is:


Membre 1 ──── N Emprunt N ──── 1 Livre
                     │
                     └──── 1 Amende



The schema uses identity columns for primary keys, unique constraints for member email and ISBN, foreign keys for referential integrity and a check constraint to prevent negative book quantities.

Tables and Constraints

Membre

The Membre table stores the member's name, email, status, member type and borrowing limit. New members are assigned the default status Actif.

The member status is constrained to Actif or Suspendu. The borrowing limit is automatically assigned by a trigger based on the member type: professors receive a limit of 10, while other member types receive a limit of 5.

Livre

The Livre table stores the ISBN, title, author and available quantity. The ISBN is unique and the Qte_dispo constraint prevents the number of available copies from becoming negative.

Emprunt

The Emprunt table records the member, book, borrowing date, due date and loan status. Foreign keys ensure that every loan references an existing member and an existing book.

Amende

The Amende table stores the loan identifier, fine amount and fine status. It is linked to Emprunt through a foreign key.

HistoriqueModifications

The audit table records the modified table, operation type, modification date and a textual description. Its default timestamp is generated with GETDATE().

Triggers

The file Script_Triggers_UA3.sql defines the following SQL Server triggers:

| Trigger | Event | Purpose |
| --- | --- | --- |
| `tr_AuditNouveauMembre` | Insert on `Membre` | Audit the insertion of a member |
| `tr_AuditNouveauLivre` | Insert on `Livre` | Audit the insertion of a book |
| `tr_AuditModifMembre` | Update on `Membre` | Audit a member update |
| `tr_AuditModifLivre` | Update on `Livre` | Audit a book update |
| `tr_AuditDelMembre` | Delete on `Membre` | Audit the deletion of a member |
| `tr_AuditDelLivre` | Delete on `Livre` | Audit the deletion of a book |
| `tr_UpdateStatutEmprunt` | Insert on `Emprunt` | Assign `En retard` or `À rendre` according to the due date |
| `tr_AuditLimiteEmpruntMembre` | Insert on `Membre` | Assign the borrowing limit based on member type |

The triggers centralize automatic actions and write audit entries to HistoriqueModifications.



Stored Procedures and Functions

sp_EnregistrerEmprunt

This procedure records a loan after checking the available quantity of the book, the member's status and the member's remaining borrowing limit. If the loan is accepted, it inserts a row into Emprunt, decreases the member's borrowing limit and decreases the available book quantity.

sp_RetournerLivre

This procedure processes a book return. It updates the loan status, calculates a penalty of $0.50 per late day, increases the available quantity of the book and restores one borrowing slot for the member. If the return is late, an unpaid fine is inserted into Amende.

sp_RapportEmpruntsRetard

This procedure returns the list of overdue loans with the member's name, book title, borrowing date, due date and number of late days.

sp_MettreAJourStatutsMembres

This procedure loops through members and suspends any member who has at least one unpaid fine. Members without unpaid fines are marked as active.

fn_VerifierEligibiliteEmprunt

The test script calls this function to verify whether a member is eligible to borrow a book. The function definition is not included among the four submitted files, so it should be added to the repository if it belongs to this project.

Test Scenarios

The file Script_Test.sql exercises the main database operations.

The script performs the following actions:

1. Selects the Bibliotheque_Universitaire database.

2. Inserts members with the types Personnel, Etudiant and Professeur.

3. Inserts books into the catalogue.

4. Displays the inserted members and books.

5. Deletes a member to test the deletion trigger.

6. Calls fn_VerifierEligibiliteEmprunt.

7. Displays the audit history.

8. Runs the overdue-loan report.

9. Updates member statuses according to unpaid fines.

10. Registers three borrowing transactions.

11. Processes three book returns.

12. Displays the final contents of Emprunt and Amende.

How to Run the Project

1. Install Microsoft SQL Server.

2. Open SQL Server Management Studio or Azure Data Studio.

3. Run Script_TablesCreation_UA3.sql first to create the database and tables.

4. Run the functions script if a separate functions file exists.

5. Run Script_StoredProcedures_UA3.sql to create the stored procedures.

6. Run Script_Triggers_UA3.sql to create the triggers.

7. Execute Script_Test.sql to populate sample records and test the operations.

8. Review the results in Membre, Livre, Emprunt, Amende and HistoriqueModifications.

The recommended execution order is:

1. Script_TablesCreation_UA3.sql

2. Script_Functions_UA3.sql

3. Script_StoredProcedures_UA3.sql

4. Script_Triggers_UA3.sql

5. Script_Test.sql
